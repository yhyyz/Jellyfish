`v0.4.0` 把 Jellyfish 从「做一条短剧」升级到「做带货短剧的工作台」。
本版本围绕 **剧情带货 (Story-Driven Commerce)** 一次性补齐数据模型、系统级 seed、LLM Agent、Worker、API、前端页面与端到端测试，并修复 v0.3.x 链路上若干路由与映射缺漏。

## Highlights

- 🛍️ **剧情带货项目类型**：`Project.kind` 引入 `drama` / `commerce`，commerce 项目走独立资产、脚本、合规链路。
- 🎬 **6 个中国市场爆款公式**：凡人逆袭 / 对比反转 / 职场逆袭 / 家庭冲突 / 悬疑反转 / 时空穿越，启动时通过 builtin seed 自动写入。
- ⚖️ **8 条 cn_mainland 合规规则 + 双引擎检查**：pyahocorasick 规则匹配 + LLM 语义判定，覆盖演绎标识、卖惨黑名单、伪造身份、群体丑化、品牌口播频次、健康类免责、不可验证宣称、虚假政策。
- 🤖 **3 个新 LLM Agent**：商品信息抽取 / 剧情脚本生成 / 合规检查，全部使用 `method="json_schema", strict=True`。
- 🔌 **22 个新 API endpoints**：覆盖 `studio/products`、`story-formulas`、`story-projects`、`story-variants`、`compliance/*` 与 `commerce/*` 异步任务。
- 🎨 **4 个新前端页面**：商品库、剧情项目大厅、剧情工作台，以及 MainLayout「🛍️ 剧情带货」submenu。
- ✅ **277 个新增测试 + 1 个 E2E smoke**：commerce 链路覆盖到位，并补齐 7 条 Alembic 迁移测试。

## Added

### 数据模型层 (Wave 1–2)

- 新增枚举：`ProjectKind`、`ProductCategory`、`FormulaRegion`、`ComplianceRegion`、`ComplianceSeverity`、`StoryVariantStatus`、`ProductRoleInStory`、`ProductAppearanceTiming`、`Platform`。
- 枚举扩展：`FileUsageKind` +3 项，`PromptCategory` +12 项 commerce 类目。
- 新增表：`products`、`product_images`、`project_product_links`、`commerce_story_configs`、`story_formulas`、`story_variants`、`story_outcomes`、`compliance_profiles`、`compliance_findings`、`api_key_quotas`。
- `Project.kind` 列：`NOT NULL DEFAULT 'drama'`，向后兼容已有项目。
- 5 条 Alembic 迁移 `0002 → 0006`，全部线性、可双向，并新增 7 条迁移测试。
- 新增 commerce 跨层 DTO 集中放在 `app/core/contracts/story.py`（遵循 AGENTS.md rule 9）。

### 系统级 Seed (Wave 3)

- `bootstrap_builtin_prompts()`：27 个模板（12 commerce + 15 legacy 修补）。
- `bootstrap_builtin_story_formulas()`：6 条 cn 公式。
- `bootstrap_builtin_compliance_profiles()`：`cn_mainland_default` profile + 8 条规则。
- 全部 idempotent，启动时由 `app.bootstrap.bootstrap_async_state` 按 `prompts → formulas → compliance` 顺序自动调用，新部署无需手动初始化。

### Agent / Worker (Wave 4–5)

- `ProductExtractorAgent` + `product_info_extract_worker`，超时 300s。
- `StoryScriptGeneratorAgent` + `story_script_generate_worker`，超时 600s，含 duration / brand frequency 校验。
- `ComplianceCheckerAgent` + `compliance_check_worker`，超时 180s，双引擎评分合并（pyahocorasick + LLM）。
- 全部 task_kind 在 `task_executor_registry` 注册，走 fast 队列。

### API 端点 (Wave 6)

- `studio/products`：`GET/POST/PATCH/DELETE /api/v1/studio/products` 及 `/{id}/images`，共 7 routes。
- `studio/story-formulas`：`GET /api/v1/studio/story-formulas` + `/{id}`，共 2 routes。
- `studio/story-projects`：`GET/POST` 列表与详情、`/{id}/config`、`/products/{pid}` 链接管理，共 6 routes。
- `studio/story-variants`：`GET/POST /api/v1/studio/story-variants`，共 2 routes。
- `studio/compliance`：`GET /api/v1/studio/compliance/profiles` + `findings`，共 3 routes。
- `commerce/*` 异步任务：`POST /api/v1/commerce/products/extract`、`script-generate`、`compliance/check`，共 3 routes。

### 前端 (Wave 8)

- `/commerce/products` ProductLibrary：商品 CRUD + URL 提取入口。
- `/commerce/projects` StoryProjectLobby：剧情带货项目大厅。
- `/commerce/projects/:id` StoryWorkbench：公式选择 + 脚本展示 + 合规面板 + 镜头时间轴。
- MainLayout 「🛍️ 剧情带货」submenu（商品库 + 剧情项目）。

### 测试覆盖 (Wave 1–9)

- **277 个新增单元/服务测试**，覆盖 W1–W8 commerce 链路。
- 1 个端到端 smoke：`backend/tests/test_commerce_e2e_smoke.py`，覆盖完整用户旅程 11 步。
- 7 条 Alembic 迁移测试覆盖 0002–0006 升降级路径。

## Changed

- 后端依赖新增：`json-repair>=0.59,<1.0`（修复 LLM JSON drift）、`pyahocorasick>=2.1,<3.0`（合规规则引擎）。
- `_PROMPT_CATEGORY_ZH` 路由映射扩展 12 个 commerce 中文条目（W7-Fix）。
- `app.bootstrap.bootstrap_async_state` 编排顺序固化为 `prompts → formulas → compliance`，保证 commerce 链路冷启动一致。
- OpenAPI 与 generated client 已按本版本接口同步更新（W7-T1）。

## Fixed

- **Celery `task_routes` globs**：旧路由匹配 `app.services.worker.*` 不命中任何已注册 task；重写为 `task.execute*` 命名空间，并按 `task.execute.video*` / `image*` / `timeline*` 分流到 slow 队列（commit `639727c`）。
- **`_PROMPT_CATEGORY_ZH` 缺新枚举翻译**：W7-Fix 补齐 12 个 commerce category 中文标签（commit `27b85b2`）。
- **`/commerce/projects` lobby 路由**：W8 阶段 race condition 漏注册，单独修复（commit `a239364`）。

## Breaking Changes

- **`Project.kind` 列添加为 `NOT NULL DEFAULT 'drama'`**：升级时 Alembic 0002 自动 backfill，但部署必须先执行 `alembic upgrade head`，否则旧 INSERT 语句缺 `kind` 字段会失败。
- **`PromptCategory` 枚举值扩展**：数据库 VARCHAR 不强制，新增的 12 个 commerce category 在旧客户端会被识别为 `(value, "")`，直到客户端升级 generated client。
- **Celery 路由命名空间收敛**：依赖旧 `app.services.worker.*` glob 进行流量分发的部署需要同步更新到 `task.execute*` 命名空间。

## Deprecations

- 本版本无显式弃用项。已有 `drama` 链路保持不变。

## Security

- `ApiKeyQuota` 表已建立但仅在 P3 阶段启用，本版本仅作为空 holder。
- 合规检查 8 条规则当前仅在 `cn_mainland` 区域生效，`overseas` / `hk_tw` 在 P2 阶段启用。
- 新增 `pyahocorasick` 依赖（BSD-3 license），已加入 backend 依赖清单。

## Known Issues

- `StoryProjectRead` 不返回 `linked products` 字段，UI 当前用全局 `useProductList` 取首条作为「主推商品」展示，P2 修复。
- W8 阶段 race condition 留下若干 commit 序列异常，但功能完整无空洞，已在 W8-Fix 阶段补齐路由。
- 预先存在的 13 个 envelope-shape (`meta: None`) 测试失败，与本次 release 无关，将在后续清理。
- 预先存在的 3 个 collection error（`test_video_capabilities`、`test_script_extract_cache`、`test_script_processing_async_api`），与本次 release 无关。

## Migration Guide

### 步骤 1 — 拉取最新代码并安装依赖

```bash
git pull
cd backend && uv sync
cd ../front && pnpm install
```

### 步骤 2 — 数据库迁移

```bash
cd backend && uv run alembic upgrade head
```

预期看到 `0002 → 0006` 共 5 条 migration 应用，新增 10 张表，`projects.kind` 列被 backfill 为 `'drama'`。

### 步骤 3 — 重启服务

启动时 `bootstrap_async_state` 会自动 seed 27 prompt templates + 6 条 cn 公式 + 8 条合规规则到 `cn_mainland_default` profile。

### 步骤 4 — 更新前端

```bash
cd front
pnpm exec tsc --noEmit   # 应通过
pnpm dev                  # 或 pnpm build 用于生产
```

### 步骤 5 — 验证

- 浏览器访问 `/commerce/products`，应看到空列表（200）。
- 浏览器访问 `/commerce/projects`，应看到空列表（200）。
- `GET /api/v1/studio/story-formulas` 应返回 6 条 cn 公式。
- `GET /api/v1/studio/compliance/profiles` 应返回 `cn_mainland_default`。

## Rollback Notes

如需回退到 `v0.3.x`：

```bash
cd backend && uv run alembic downgrade 0001   # 回退所有 commerce 迁移
git checkout v0.3.2
```

注意：已创建的 commerce 项目数据会丢失（10 张表会被 drop）。建议升级前 `mysqldump` 备份。
若已有用户数据进入 commerce 链路，优先采用「保留表 + 关闭入口」的兼容回滚策略，而非直接 downgrade。

## Notes for Contributors

- AGENTS.md rule 4：`api` / `service` 严格分层，commerce 路由在 `routes/` 仅做收参与响应组装，业务逻辑下沉到 service。
- AGENTS.md rule 9：跨层 DTO 统一放在 `app/core/contracts`；`tasks` 仅做封装与编排，不定义跨层 DTO。
- 决策记录 D5：新 commerce agents 必须使用 `method="json_schema", strict=True`。
- 新增公式或合规规则时，优先扩展 `bootstrap_builtin_*` seed，不要破坏现有数据。
- 状态语义保持 `shot.status`（信息确认） / runtime task status / `video-readiness` 三类分离的约定不变。
