`v0.6.0` 把剧情带货从「文本结构生产级」推进到「视觉生产级」。本版本是 W16 ~ W21 的整合发布，主线是把音视频能力从配角升级为一等公民：r2v 支持多图参考，TTS 走 `silent_with_tts` 与 `keep_native` 双路径，字幕引擎覆盖三平台模板，章节级 `chapter_av_export` 把 5 段管线打通成可用成片。

前端工作室同步升级：3 个新组件（ProductImageGrid / VoicePackPicker / SubtitleStylePicker）+ 2 个商品视觉库页（音色库 / 字幕样式库）+ AVPreviewPanel 抽屉，全部走 Vitest 2.1.9 + RTL TDD，共 24 个 cases 兜底。后端补齐两条只读 HTTP API（`/commerce/voice-packs` 与 `/commerce/subtitle-styles`）并通过 OpenAPI 同步到前端 generated client。`backend/scripts/p3_e2e_smoke.py` 把 W19b 验证脚本固化成可重复执行的 5 段管线 e2e（4 个 offline TDD cases），并配套 3 篇 how-to guide 与 1 篇 architecture 章节。

## Highlights

- 🎬 **r2v 多图参考落地**：单镜头支持上限 8 张关键帧 + 风格参考图组合输入，固化「商品视觉一致性」契约。
- 🎙️ **TTS 双路径并存**：`silent_with_tts`（合成配音）与 `keep_native`（保留 r2v 自带原音 + ASR 反推字幕）共用统一 audio_strategy，无需调用方分支。
- 📺 **字幕引擎三平台模板**：`douyin_default` / `kuaishou_default` / `wechat_default` + colorCodec helper，安全区硬烧 ASS derivative。
- 🧩 **chapter_av_export 章节合成**：5 段管线（项目准备 / 镜头建模 / r2v 多图视频 / ASR + 字幕渲染 / 章节合成）一次产出 1080×1920 H.264 + AAC 成片，含 loudnorm 响度归一与字幕硬烧。
- 🎨 **前端工作室升级**：3 组件 + 2 库页 + AVPreviewPanel 抽屉，i18n commerce 命名空间 6 子 ns 全量覆盖。
- ⚙️ **Vitest 2.1.9 + RTL + jsdom 测试基建**：24 个前端 TDD cases 兜底，p3_e2e_smoke.py 固化 4 个 offline 后端 cases。

## Added

### 数据模型层

- 商品视觉相关字段并入 `product_assets` 与 `shot_video_jobs`，支持 r2v 多图参考与 audio_strategy 二选一持久化。
- `voice_packs` / `subtitle_styles` 两张系统级只读表，启动时自动 seed（音色库 + 三平台字幕模板）。
- `chapter_av_exports` 表记录章节级合成产物（5 段管线最终输出 + 中间 ASR / subtitle / loudnorm 元数据）。

### Worker / 管线

- `r2v_multi_reference` 输入契约：单 job 接受 keyframes[] + style_refs[]，按 narrative order 拼接进 r2v provider。
- `audio_strategy=keep_native` 链式调度：r2v 完成后自动派发 ASR 反推 + subtitle 渲染（W19b 已固化 commit-before-dispatch 契约）。
- `chapter_av_export` 5 段管线 executor：项目准备 → 镜头建模 → r2v 多图视频 → ASR + 字幕渲染 → 章节合成（loudnorm + 字幕硬烧 + ASS derivative）。
- `backend/scripts/p3_e2e_smoke.py` 固化 W19b 验证脚本为可重复执行入口（commit `bcda32d`）：
  - `--help` 模式输出 5 段管线说明。
  - `--dry-run --product-id <pid>` 模式打通离线契约验证（4 个 TDD cases）。
  - production 模式直接调用 `POST /api/v1/studio/chapters/{id}/av-export`。

## Changed

- 前端 OpenAPI generated client 重新生成，覆盖 `voice-packs` / `subtitle-styles` 两条新路由与 `VoicePackRead` / `SubtitleStyleRead` 两个 schema。
- StoryWorkbench 主入口集成 AVPreviewPanel 抽屉，章节合成不再需要独立路由。
- W19b 已落地的 dev DB 推荐路径（MySQL 8 + READ COMMITTED + aiomysql `init_command` + sync engine NullPool）作为 v0.6.0 标准 dev 配置写入文档。
- `commerce.json` i18n 文件改为「预创建 stub + 严格 append-only」写入策略，化解三方并行 wave 的 race condition。
- `chapter_av_export` 替代 `chapter_timeline_export` 成为章节级合成正式入口，旧入口保留兼容但不再扩展。

## Breaking Changes

- **`chapter_av_export` 替代 `chapter_timeline_export`**：
  - 影响范围：章节级合成入口路由与 task_kind。
  - 旧入口在 v0.6.0 仍兼容运行，但**计划在 v0.7.0 删除**。
  - 调用方需在 v0.6.0 ~ v0.7.0 窗口内迁移：`POST /api/v1/studio/chapters/{id}/timeline-export` → `POST /api/v1/studio/chapters/{id}/av-export`。
- **create endpoint 重复 ID 错误码 400 → 409**（W19b 已切换，v0.6.0 正式纳入版本契约）：
  - 影响范围：`POST /api/v1/studio/products`、`POST /api/v1/commerce/story-projects` 等所有 create 路由。
  - 调用方必须更新错误码处理：`409` 表示资源已存在，`400` 现在仅用于参数校验失败。
- **dev DB 推荐切 MySQL 8**：SQLite 在 4+ 并发 r2v worker 写入场景下不再保证稳定，功能仍兼容但不再作为推荐 dev 配置。

## Deprecations

- `chapter_timeline_export` 入口与对应 task_kind 标记为 deprecated，将在 v0.7.0 删除。
- 直接读 `commerce.json` 的旧前端调用路径不再扩展，新组件统一走 OpenAPI generated client（AGENTS.md 规则 2 要求）。

## Security

- 无新增三方依赖、无凭证轮换。
- `voice_packs` / `subtitle_styles` 表为系统级只读，仅 bootstrap 阶段写入，HTTP API 层不暴露写路径。
- ASR 反推字幕走本地化处理链，不外传音频原始数据，与 W19b 安全边界一致。
- aiomysql `init_command` 注入仅作用于 SESSION 级隔离级别，不修改 DB 全局配置（继承 W19b 决策）。

## Known Issues

- ASR 反推字幕在 `audio_strategy=keep_native` 路径下依赖 r2v 输出包含可识别人声，纯环境音 r2v 输出会得到空字幕（属预期行为，不计失败）。
- chapter_av_export 全链路（5 路 r2v + ASR + render + export）总耗时约 680s，r2v 与 ASR 之间尚未并行调度。
- 预先存在的 13 个 envelope-shape (`meta: None`) 测试失败与 3 个 collection error 与本 release 无关，待后续清理（与 v0.5.0 已知问题一致）。
- SQLite 在 dev 环境若仍坚持使用，需手动设置 `JF_DB_BUSY_TIMEOUT=60` 且并发 worker 数 ≤ 2（W19b 已知约束延续）。

## Migration Guide

### 步骤 1 — 拉取最新代码并安装依赖

```bash
git pull
cd backend && uv sync
cd ../front && pnpm install
```

### 步骤 2 — 数据库迁移

```bash
cd backend && uv run alembic upgrade head
```

预期：`voice_packs` / `subtitle_styles` / `chapter_av_exports` 表创建完成，bootstrap 自动 seed 音色库与三平台字幕模板。

### 步骤 3 — 同步 OpenAPI generated client

```bash
cd front && pnpm run openapi:update
```

预期：`front/src/services/generated/` 出现 `VoicePackRead` / `SubtitleStyleRead` 与 `/commerce/voice-packs` / `/commerce/subtitle-styles` 调用方法。

### 步骤 4 — 重启 backend 与 celery worker

```bash
cd backend
uv run uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
uv run celery -A app.worker_app worker -l info
```

旧连接池需丢弃，确保新 task_kind（`chapter_av_export` / r2v 多图） registry 生效。

### 步骤 5 — 客户端错误码迁移（如未在 W19b 升级阶段完成）

```diff
- if response.status_code == 400 and "already exists" in body:
+ if response.status_code == 409:
      handle_duplicate_resource()
```

### 步骤 6 — 旧 chapter_timeline_export 调用迁移

```diff
- POST /api/v1/studio/chapters/{id}/timeline-export
+ POST /api/v1/studio/chapters/{id}/av-export
```

v0.7.0 将删除旧入口，请在升级窗口内完成切换。

## Rollback Notes

如需回退到 `v0.5.0`：

```bash
cd backend && uv run alembic downgrade <v0.5.0-baseline>
git checkout v0.5.0
```

注意：

- 回退后 `voice_packs` / `subtitle_styles` / `chapter_av_exports` 表 drop，对应 seed 数据丢失。
- W19b 在 v0.5.0 之上以独立 wave 形式发布，回退到 `v0.5.0` 标签会同时丢失 W19b 修复，建议优先回退到 W19b 节点（commit `5446050..2597db8`）：

```bash
git checkout 2597db8
```

- 已生成的章节合成产物（`chapter_av_exports` 行）回退后失去 lookup 目标，但成片文件本身保留在对象存储中。
- 升级前建议 `mysqldump` 备份。

## Notes for Contributors

- 新写跨 worker chain dispatch 必须遵守 W19b **commit-before-send_task** 契约：service 层显式 `await session.commit()` 后再 `send_task`，禁止依赖默认事务自动提交。
- 新增前端组件必须先写 Vitest TDD（Red → Green），统一在 `__tests__/` 同级目录，jsdom + RTL + userEvent 三件套已就绪。
- i18n commerce 命名空间走「预创建 stub + 严格 append-only」策略，禁止覆盖式写入；新增子 ns 时同步更新 6 子 ns 表。
- 商品视觉相关跨层 DTO 统一放 `app/core/contracts/`（AGENTS.md 规则 9），`tasks` 仅做封装与分派，不再持有 DTO 定义。
- chapter_av_export 5 段管线属于稳定契约，新增管线段必须先在 `architecture/commerce-story-data-model.md` 的 Visual Production Layer 章节登记，再落代码。
- `shot.status` 仅表「信息确认状态」，不混入运行时与视频准备度（与 v0.5.0 一致），运行时状态来自任务系统，video-readiness 单独表达。
