`v0.7.1` 是 v0.7.0「P5 收官」之上的**安全加固 + 隐患收尾** hotfix 版本。本版本聚焦三件事：把 v0.7.0 Deprecations 节标的「W32 双轨过渡期结束」按时落地（`jwt_fallback_to_static` 默认 `False` + `BOOTSTRAP_ADMIN_PASSWORD` 启动期硬校验）、把 W30 / W31 sub-agent 复盘披露的 2 处隐患（subtitle_styles 并发 race / SFX offset 写死 0）补完、把 W32 上线后两轮 manual QA 发现的主路由 RBAC 守卫缺口固化。alembic 链从 v0.7.0 末态 `0021` 推进到 v0.7.1 末态 `0023`（2 个独立 migration，单 wave 可回滚）。

升级到 v0.7.1 是**强烈推荐**的：它是 v0.7.0 的 P0 修补包，所有部署都应跟进。production / staging 部署还会触发**新增的启动期 sanity check**——如果 `BOOTSTRAP_ADMIN_PASSWORD` 或 `SECRET_KEY` 仍是默认占位值，应用会直接 `RuntimeError` 阻塞启动；这个行为对 dev 环境只是 warning，对 production-like env 是硬阻塞。

## Highlights

- **安全加固**：`jwt_fallback_to_static` 默认从 `True` 翻成 `False`，关闭旧 `api_key` 静态 token 兼容路径；`BOOTSTRAP_ADMIN_PASSWORD` / `SECRET_KEY` 仍是默认占位值时 production-like env 启动直接 `RuntimeError`。
- **W30 并发隐患修复**：`subtitle_styles` 在 DB 层补了 `(project_id, name)` UNIQUE 约束（generated column `_scope_key` + UNIQUE 索引），双重防护并发 POST 同 name 写入；service 层 `IntegrityError → HTTP 409` 兜底。
- **W31 SFX 时间轴接通**：`ChapterTimelineSegment.sfx_offset_ms` 列上线，AVPreviewPanel 加 0–30000ms 滑块；之前 `chapter_av_export` 把 SFX offset 写死成 0 的退化路径彻底打通。
- **主路由 ProtectedRoute 修复**：W32-followup-2 把 `MainLayout` 接到 `AuthContext`，主路由统一走 `ProtectedRoute` 守卫；之前 W32 第一轮上线时 RBAC 仅 API 层守住，路由层用 `useEffect` 软拦截存在闪烁与刷新空白漏洞。

## Fixed

- **W32-followup（commit `2c8b02d`，已在 v0.7.0 base 落地）**：`GET /api/v1/users/me` 端点 + `AuthContext` 拉真实 role；之前 `useUser` hook 拿 `null` 导致 RBAC 检查全部 fallback 到匿名。
- **W32-followup-2（commit `3bf6849`）**：主路由 `ProtectedRoute` 守卫 + `MainLayout` 接 `AuthContext` + vite proxy env 修正；解决"刷新页面短暂出现 admin-only UI"等闪烁问题。
- **W30-followup（本版本 commit `247f489`）**：`subtitle_styles (project_id, name)` UNIQUE 约束 + `IntegrityError → HTTP 409` 兜底。
- **W31-followup（本版本 commit `b753afd`）**：`ChapterTimelineSegment.sfx_offset_ms` 列 + `AVPreviewPanel` Slider + `chapter_av_export_filter` adelay 用真实值。

## Breaking Changes

1. **`settings.jwt_fallback_to_static` 默认值翻转**：`True → False`。
   - 影响：所有依赖 `Authorization: Bearer <api_key>` 静态 token 的客户端会立刻 401；必须切换到 `POST /api/v1/login/access-token` 拿 JWT。
   - 临时回滚：`.env` 里设 `JWT_FALLBACK_TO_STATIC=true` 续命；P6 起会彻底删除该 fallback 分支，临时窗口仅作迁移用。

2. **production-like env 启动期 reject 默认密码**：`JELLYFISH_ENV in {production, prod, staging}` 时 `BOOTSTRAP_ADMIN_PASSWORD == 'changeme'` 直接 `RuntimeError`。
   - 影响：跑过 docker-compose 默认 `.env` 的旧部署在升级到 v0.7.1 后启动失败。
   - 修复：在 `.env` 中显式设置 `BOOTSTRAP_ADMIN_PASSWORD=<your-strong-password>`。

3. **production-like env 启动期 reject 默认 SECRET_KEY**：同上策略。
   - 影响：旧部署没有改 `SECRET_KEY` 的会启动失败。
   - 修复：`SECRET_KEY=$(openssl rand -hex 32)` 写入 `.env`。

## Deprecations

- `JWT_FALLBACK_TO_STATIC=true` 仍可临时开启，但已标记废弃。**P6 起会彻底删除该分支**。请在升级到 v0.7.1 后立即把所有调用方迁移到 JWT。

## Security

- `jwt_fallback_to_static` 默认禁用关闭了"`api_key` 泄露 = root 账号被夺"的攻击面。`api_key` 之前同时承担「内部服务调用」与「admin 身份代理」两个角色，泄露代价过高。
- `BOOTSTRAP_ADMIN_PASSWORD` / `SECRET_KEY` 启动期硬校验防止"忘记改默认值就直接上 production"的低级失误。
- 启动期 sanity check 模块 (`app/core/security_checks.py`) 后续可挂载更多检查（SMTP 凭据、S3 凭据、CORS 通配等）。

## Migration Guide

从 v0.7.0 升级到 v0.7.1 的推荐流程：

1. **拉取代码**
   ```bash
   git fetch origin
   git checkout dev   # 或 main，按贵团队部署分支
   git pull
   ```

2. **`.env` 必须改**（production / staging 必做，dev 推荐做）
   ```bash
   # production / staging 部署：
   echo "JELLYFISH_ENV=production" >> backend/.env
   echo "BOOTSTRAP_ADMIN_PASSWORD=$(openssl rand -hex 16)" >> backend/.env
   echo "SECRET_KEY=$(openssl rand -hex 32)" >> backend/.env
   # 已部署且 admin 用户已创建：BOOTSTRAP_ADMIN_PASSWORD 改了不影响已存在用户
   ```

3. **alembic 升级**：`0021 → 0023`
   ```bash
   cd backend
   uv run alembic upgrade head
   # 期望输出：Running upgrade 0021 -> 0022（subtitle_styles UNIQUE）
   #           Running upgrade 0022 -> 0023（chapter_segment sfx_offset_ms）
   ```

4. **客户端迁移到 JWT**（如果之前用 `api_key` 静态 token）
   ```bash
   # 之前：
   curl -H "Authorization: Bearer ${API_KEY}" ${BACKEND}/api/v1/...
   # 现在：先登录拿 access_token
   TOKEN=$(curl -s -X POST ${BACKEND}/api/v1/login/access-token \
     -d 'username=admin&password=...' | jq -r .data.access_token)
   curl -H "Authorization: Bearer ${TOKEN}" ${BACKEND}/api/v1/...
   ```
   迁移期内可临时设 `JWT_FALLBACK_TO_STATIC=true` 续命。

5. **重启服务**
   ```bash
   # production sanity check 通过后才会启动
   docker compose -f deploy/compose/docker-compose.yml restart backend
   ```

6. **前端清缓存**：`v0.7.1` 修改了主路由守卫逻辑，让用户清一次浏览器 localStorage（或在 DevTools → Application 删 `jellyfish-token`）确保拿到新版 `MainLayout` 的 `AuthContext` 行为。

## Rollback Notes

如需回滚到 v0.7.0：

```bash
# 1. 反向降级 alembic（0023 → 0021）
cd backend
uv run alembic downgrade 0021

# 2. git revert 三个 fix commit 与 release note commit
git revert <release-note-sha>     # commit 4
git revert 0f93ff1                # commit 3：security
git revert b753afd                # commit 2：sfx_offset_ms
git revert 247f489                # commit 1：subtitle_styles UNIQUE

# 3. 如果之前已经把 BOOTSTRAP_ADMIN_PASSWORD / SECRET_KEY 改回默认值
#    JELLYFISH_ENV=production 启动会再次被 sanity check 拦下；
#    rollback 到 v0.7.0 后需要把 .env 里的覆盖值回写回去。
```

注意：`subtitle_styles._scope_key` 生成列在 downgrade 时会被 drop；如果在 0023 上线后有项目级行的 name 与系统级行 name 完全相同（这本来就是 0022 兜底防的场景），降级后这部分约束消失但脏数据不会回退。

## Validation Commands

升级完成后可逐项验证：

```bash
# 1. alembic head 推到 0023
cd backend && uv run alembic current
# 期望：0023 (head)

# 2. 主流程 RBAC smoke（5 case）—— 必须在登录后
curl -s -H "Authorization: Bearer ${TOKEN}" \
  ${BACKEND}/api/v1/users/me                 # ✓ 200
curl -s -H "Authorization: Bearer ${TOKEN}" \
  ${BACKEND}/api/v1/commerce/projects        # ✓ 200
curl -s ${BACKEND}/api/v1/commerce/projects  # ✓ 401 (无 token)
# 用 viewer role 的 token：
curl -s -X POST -H "Authorization: Bearer ${VIEWER_TOKEN}" \
  ${BACKEND}/api/v1/commerce/projects \
  -H "Content-Type: application/json" -d '{}'  # ✓ 403 (RBAC reject)

# 3. subtitle_styles UNIQUE 约束（双重 POST 同 name 在 service SELECT 命中）
curl -s -X POST -H "Authorization: Bearer ${TOKEN}" \
  ${BACKEND}/api/v1/commerce/projects/${PROJ}/subtitle-styles \
  -H "Content-Type: application/json" \
  -d '{"name":"my_style", ...}'             # ✓ 第一次 201
curl -s -X POST -H "Authorization: Bearer ${TOKEN}" \
  ${BACKEND}/api/v1/commerce/projects/${PROJ}/subtitle-styles \
  -H "Content-Type: application/json" \
  -d '{"name":"my_style", ...}'             # ✓ 第二次 409

# 4. AVPreviewPanel 上 SFX offset slider 可见（full mode）
# 在浏览器打开分镜工作室 → 选 segment → 切 audio_mix_mode=full →
# 应看到 SFX 文件下拉 + SFX 起始偏移 slider + ducking slider
```

## Notes for Contributors

- `app/core/security_checks.py` 是新落点，未来类似启动期硬约束（SMTP / S3 凭据等）应集中放这里。
- alembic 0022 的 `_scope_key` 生成列在 MySQL 8 走 `VIRTUAL`、SQLite 走 `STORED`——这是因为 MySQL 8 在带 FK 的表上 `ALTER TABLE ADD STORED` 会触发 `Cannot add foreign key constraint` (Error 1215) 表 rebuild 失败；后续给其它有 FK 的表加生成列时按同一策略。
- v0.7.1 不修改 `architecture` / `plans` 文档：本版本是行为 / 安全 hotfix，业务边界没动，等到 P6 起 `JWT_FALLBACK_TO_STATIC` 真正删除时再统一刷一波 architecture。
