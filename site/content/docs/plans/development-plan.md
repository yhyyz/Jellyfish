当前项目核心流程、数据模型、生成准备架构与任务异步体系都已基本稳定。下一阶段不再以"结构治理"为主线，而是聚焦在两条仍未启动的方向：

1. 提示词系统化优化
2. 剪辑边界判断

## 一、提示词系统化优化

当前项目已经包含多个 Agent，分别承担剧本处理、资产提取、图片生成、关键帧生成等任务。每个链路上都有自己的提示词，但整体仍缺少统一治理。

### 现状

- 提示词散落在不同 Agent 与服务中，缺乏统一的版本管理
- 各类提示词没有明确的分类与责任边界
- 缺少系统化的效果对比手段，难以判断改动是变好还是变差
- 上线后的产出质量主要靠"看起来差不多"判断

### 拟解决的问题

**1. 提示词分类治理**

需要把当前所有提示词按用途归类，至少包含：

- 图片生成类（角色、演员、场景、道具、服装、关键帧）
- 剧本处理类（优化、简化、一致性检查、信息提取）
- 镜头语义类（动作拍点、构图重心、视线朝向、连续性引导）

每一类要有自己的输入约定、输出约定与质量要求。

**2. A/B 测试能力**

需要支持对同一节点同时运行多个版本的提示词，并采集：

- 输出可解析率
- 字段完整率
- 同项目内一致性表现
- 人工反馈记录

否则提示词调整只能凭直觉，无法形成可演进的系统。

**3. 与项目业务的对齐**

不追求"通用提示词工程"。所有调整都围绕：

- 同一项目内的角色、场景、道具一致性
- 镜头之间的视觉与轴线连续性
- 关键帧"触发 / 峰值 / 收束"语义稳定

### 不在本阶段范围

- 提示词模板的可视化编辑器
- 提示词市场或共享机制
- 跨项目共享的"通用最佳实践"

这一方向当前未启动。后续将先从"分类盘点"开始，再决定是否引入 A/B 测试基础设施。

## 二、剪辑边界判断

当前剪辑能力定位为"够用、能衔接导出"。具体现状是：

- 能管理素材
- 有基本的时间线
- 能完成导出
- 不与专业视频编辑器在功能广度上竞争

### 待判断的问题

剪辑这条路，未来要继续保持"够用"，还是要明确投入？这个决策当前没有结论。两条候选路径：

**路径 A：继续保持"够用"**

- 不再扩展剪辑能力
- 重心放在生成质量与素材衔接
- 用户复杂剪辑需求引导到外部专业工具

**路径 B：引入轻量专业能力**

可能的方向包括：

- 增强 timeline 编辑器（多轨道、关键帧动画、转场预设）
- 引入 ffmpeg 驱动的批处理能力（批量裁切、合成、字幕烧录）
- 提供模板化剪辑流程（短剧拼接、片头片尾自动套用）

### 判断依据

是否推进路径 B，主要看：

1. 用户是否在导出后还在外部工具中做大量剪辑工作
2. 现有"够用"剪辑流程是否成为生成主链的瓶颈
3. 是否有清晰的差异化路径，而不是与 CapCut / Premiere 同质竞争

这一方向当前未启动。在没有明确证据支撑路径 B 之前，默认走路径 A。
